# Insights (Step 11)

Insights consumes the capability-gated `readEvents` APIs of Projects, Issues, Wiki, Coordination, Planning and Assets. Each owner has a workspace-local sequence cursor. A D1 batch inserts activity rows and advances the corresponding cursor with a CAS guard. Replays use `(workspace_id, source, sequence)` and `(workspace_id, source, event_id)` uniqueness. A missing sequence or unsupported schema version aborts that owner’s batch without acknowledging any of its events. The scheduled Worker handler enumerates every active workspace through Access’s composition-only, keyset-paged `background.listActiveWorkspaceIds` capability and consumes up to 100 events per owner per workspace each tick; an authorized read seeds a workspace and performs a bounded catch-up of 30 events per owner. The lag fields show the last committed sequence and time, or `null` before any event was consumed.

Activity stores event identifiers, type, actor, optional client ID and time; it stores no issue/wiki body. Before returning an item, Insights resolves its target through the source owner's public query and the caller's current scope. Archived or newly inaccessible targets are omitted. Project filters are applied after authorization. The keyset cursor orders by event time, source and sequence. Project metrics are calculated from currently visible Issues state and history, plus Coordination's live lease/session queries; the `insights_metrics` row is only a snapshot of the latest calculation. It is never used to authorize or answer a read. Completion counts include transitions to `done` in the preceding 7 and 30 days, grouped by actor and the Issues history client ID.

Subscriptions and read markers have workspace/principal scoped operation receipts and versioned CAS updates. Notification candidates are derived from the projected Issue event version and authorized Issue history on read; `assigned`, watched `comment` and issue lease changes are supported. Notifications contain no comment body. The list checks the issue's current visibility before returning rows or an unread count. External delivery is outside this owner.

Projects, Coordination, Planning and Assets now emit schemaVersion 2 events with nullable `payload.clientId` captured from RequestScope. Their immutable version-1 rows remain readable with null attribution; Insights accepts versions 1 and 2 for those four owners and version 1 for Issues/Wiki. Historical client IDs cannot be reconstructed. Coordination version-2 `FileClaimForced` retains its path subject and adds `issueId` / `projectId` from the manager’s fenced lease. Insights uses the issue ID to perform live authorization and locate the project; version-1 forced claims without a target remain omitted.

`consumeEvents` is a composition-only factory capability, absent from `InsightsApi` and the object passed to Gateway. Workspace enumeration is similarly absent from `AccessApi`. Gateway cannot import either factory. There is no HTTP/MCP consumer or discovery endpoint, even for workspace owners. `drainKnownWorkspaces` was removed: it could miss unread workspaces and repeatedly select only the first page.

The 7/30-day metrics include both endpoints of `[now - days * 86400, now]`, excluding future timestamps. `markRead` retries reauthorize their target before returning the saved receipt. Reads remain bounded catch-ups rather than guaranteed zero-lag views; scheduled ticks page all active workspaces but consume only 100 events per source per tick, so a sustained higher arrival rate accumulates lag. Discovery is keyset traversal, not an atomic workspace snapshot; a workspace created behind the cursor is found next tick. Tests cover local Miniflare D1 and headless browser behavior; deployed cron execution and production scale remain unverified.
