# Insights (Step 11)

Insights consumes the capability-gated `readEvents` APIs of Projects, Issues, Wiki, Coordination, Planning and Assets. Each owner has a workspace-local sequence cursor. A D1 batch inserts activity rows and advances the corresponding cursor with a CAS guard. Replays use `(workspace_id, source, sequence)` and `(workspace_id, source, event_id)` uniqueness. A missing sequence aborts consumption. The scheduled Worker handler drains workspaces that have appeared in the cursor table; an authorized read seeds a workspace and performs a bounded catch-up of 30 events per owner. The lag fields show the last committed sequence and time, or `null` before any event was consumed.

Activity stores event identifiers, type, actor, optional client ID and time; it stores no issue/wiki body. Before returning an item, Insights resolves its target through the source owner's public query and the caller's current scope. Archived or newly inaccessible targets are omitted. Project filters are applied after authorization. The keyset cursor orders by event time, source and sequence. Project metrics are calculated from currently visible Issues state and history, plus Coordination's live lease/session queries; the `insights_metrics` row is only a snapshot of the latest calculation. It is never used to authorize or answer a read. Completion counts include transitions to `done` in the preceding 7 and 30 days, grouped by actor and the Issues history client ID.

Subscriptions and read markers have workspace/principal scoped operation receipts and versioned CAS updates. Notification candidates are derived from the projected Issue event version and authorized Issue history on read; `assigned`, watched `comment` and issue lease changes are supported. Notifications contain no comment body. The list checks the issue's current visibility before returning rows or an unread count. External delivery is outside this owner.

Existing producer event contracts carry client IDs for Issues and Wiki, but Projects, Coordination, Planning and Assets events carry only actor IDs. Insights returns `clientId: null` for those events. Historical client attribution for those owners requires a later producer-contract migration; it cannot be reconstructed from their current public events. Coordination `FileClaimForced` events have no issue/project identifier in the public contract, so they cannot be shown in a project feed without an upstream contract extension. Scheduled consumption discovers a workspace after its first authorized Insights read because Access currently exposes no unscoped workspace enumeration to background consumers.
