# 所有権と公開境界の検査

`module-registry.json` の module は状態・規則の所有者です。ファイル内の役割は別の `@role` で示します。ファイル数をモジュール数として扱いません。

- 他の所有者への import は、型だけの import も含め、宣言された入口と名前付き export に限定します。
- 既存の非公開ファイルから公開する名前を限定できます。宣言していない名前は namespace import や再 export でも利用できません。public 役割の入口では export 一覧全体を宣言します。
- assembly は指定された composition から、transaction SPI は指定された内部役割・ファイルからだけ利用できます。
- test SPI は指定したテストファイルと export に限定します。本番コードの例外にはなりません。
- controller の JSX、view の状態フック・通信・ブラウザ保存操作、composition 内の直接 D1 操作など、決めた役割規則を検査します。
- 実ファイルの実行時循環は失敗します。所有者をまとめたグラフの循環は具体的な経路を報告し、公開入口だけの循環は失敗します。transaction SPI を含む所有者の循環は、その一覧を人が確認します。
- 変更しない移行 SQL、第三者コード、生成物、JSON もレジストリで分類します。生成物の分類自体は、現在のソースから生成した証明にはなりません。

実行: `npm run check:architecture` と `npm run test:architecture`。
`npm run verify:local` は型検査、lint、build に続いて両方を実行します。ポリシーを自動生成・承認する処理はありません。

この検査は宣言済み境界と限定した構文規則を守るためのものです。単一責任、業務仕様、認可の正しさを証明するものではなく、コードとポリシーのレビューおよび動作試験を置き換えません。レジストリや検査コード自体を変更できる人による回避も防止しません。
