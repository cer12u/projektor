# Restored P2-03 integration fixture

Run from the package with `npm run test:p2-03`. An optional first argument is a case-name regular expression, for example `npm run test:p2-03 -- '^Confirmed operation'`.

- All 20 original case names and test purposes are retained from `auth-release/candidate/scripts/p2-03-integration.mjs` (SHA-256 `2ed771df3046deb5563440b2561b348cc01818e56955895476341d57de929bc7`). The original auth baseline is retained byte for byte at `docs/p2-02-openapi-baseline.json` (SHA-256 `6ebac2fb11726abf0bac6c0a69c2fbfd9294ed0402bde619d3dbf5ba53d6cf8c`). Recovery provenance is an external verification artifact, not a second test suite.
- Wrangler's installed local CLI applies every canonical `migrations/*.sql` migration. The suite verifies the ordered `d1_migrations` ledger. It does not parse SQL, use a reconstructed schema, or select only the original four migrations.
- All database state is synthetic and temporary. Both Wrangler configurations use a zero UUID local database, `remote: false`, loopback HTTP and the same disposable persistence directory. Fixture endpoints never enter the product worker. Child processes receive a narrow environment allowlist and a temporary HOME; no cloud credentials are required or inherited.
- Reports and runtime/migration logs default to package-local `.local/evidence`. `P2_EVIDENCE_DIR` can redirect verification artifacts. Each invocation first replaces the latest report with `passed: false`; invalid regexes and zero matches exit nonzero with fresh failed evidence. Filtered runs have `mode: filtered` and never set `fullSuitePassed`, even if their selected cases pass. Required setup cases are labeled `dependency` rather than counted as selected cases. The database is removed after the runtime exits.

## Compatibility repairs, with current contract evidence

1. `migrations/0006_browser_exchange.sql` adds `sessions.scope_ceiling_json`. The original positional nine-value session insert therefore fails on the canonical schema. Fixture inserts now name their columns explicitly, allowing the nullable new column to retain its default. The fixture also seeds synthetic workspace/project records introduced by `migrations/0011_import_model.sql`; `src/worker/issues.ts` derives current `workspaceId` and issue `number` from those records.
2. `src/worker/issues.ts#getIssueHistory` and `docs/openapi.json#/components/schemas/IssueHistoryPage` include resolution events and a separate resolution cursor. The existing empty-history assertion now checks the complete current empty response, including `resolutionEvents: []` and `nextResolutionAfterRevision: null`. The existing ordered revisions, page bounds, ordinary cursor and history assertions are retained.
3. The current Issue contract contains `anyOf`, `allOf` and nullable references that the original small recursive validator cannot interpret. The original OpenAPI case now validates actual current read/history/result bodies with the already locked Ajv dependency, as used by `scripts/check-public-openapi.mjs`. Negative witnesses verify that it rejects extra response properties and a zero revision.
4. The current public OpenAPI contract intentionally enriches the original auth routes with response policies, cache headers, refusal restrictions, route metadata and closed object schemas. Exact equality of entire historical route objects would reject those documented additions. The same original OpenAPI case instead asserts all original route/method identities, authentication alternatives, status codes, response JSON schemas/value constraints, request-body required flags, input schemas and required parameters; exact equality of original security schemes; and the complete original auth schemas with the documented `additionalProperties: false` tightening for Principal, Project, Identity and Error. Inline health/login/logout responses retain their exact values while adding required fields and closed objects; context adds the documented token pattern; only 401/403 error schemas gain the exact nondisclosure constraint. Negative witnesses reject a missing required login body, changed logout value and removed failure JSON. It validates real Bearer and Cookie identity responses against both current and historical schemas. The only parameter-pattern evolution admitted is the explicit project identifier widening to `[A-Za-z0-9_-]{1,128}`, matching `src/worker/index.ts`, `src/worker/issues.ts#validateIssueRoute` and the current spec. The original baseline file is not regenerated or overwritten.

No product source, distribution, migrations, or primary Wrangler configuration is changed by this restoration. Responses discarded by the host remain explicitly labeled simulations of response loss, not real network partitions or acknowledgement faults.
