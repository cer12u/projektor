# Projektor 修正の最上位設計制約

ユーザー指定（2026-10-12）により、docs/architecture-spec.md をこのプロジェクトの設計・実装・テストの最上位仕様とする。

- 既存実装、過去の設計、API契約、テストの期待値が衝突した場合は architecture-spec.md を優先する。旧挙動を守るために仕様を曲げない。
- 設計された責務・状態所有・依存方向・原子性を実装する。ラッパー追加、ファイル移動、タグ付け、テスト件数だけで完了としない。
- 業務規則とユースケースはD1/SQL/Cloudflare実装をimportしない。型付きの具体的な読取り・一括確定・結果照会契約に依存する。
- 権限・版・更新・履歴・操作結果を原子的に扱い、失敗理由と適用確度と開示可否を区別する。
- データ・履歴・識別子を破壊しない。旧互換層は必要性が説明できる移行用途だけに限定する。
- テストは新仕様の不具合仮説に基づく。既存テストを削除/変更する場合は仕様上の理由を残す。仕様に反する期待値を保護しない。
- 本番の認証設定、資格、配備、DB操作はローカル修正の承認に含めない。承認済み範囲と安全要件に従う。
- 完了は全経路の仕様適合と対応する証拠で示す。未実装・未確認・拒否された検証を明示する。
